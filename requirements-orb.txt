# The optional ORB model family (fastmd.adapters.orb): orb-models 0.5.4 (ORB v3), plus the packages it imports that
# a PyTorch environment lacks. Exact versions, each with the sha256 of its PyPI file.
#
# Platforms: the platform wheels are the Linux aarch64 ones (Grace CPUs, e.g. GB200): dm-tree (cp312) and
# cryptography (cp311-abi3: CPython 3.11 and later, glibc 2.34 and later). The others are pure Python. An x86_64
# environment needs its own hashes for those two files (PyPI has x86_64 wheels of both; a requirement may list
# several --hash options).
#
# Install over an environment that already runs fastmd, in a virtual environment that sees its packages:
#
#   python -m venv --system-site-packages <venv>
#   <venv>/bin/python -m pip install --no-deps --require-hashes -r requirements-orb.txt
#
# These pins come from MD's tools/ci/orb_lane.sh; that script is not shipped with FastMD.
# Normal installation uses pyproject.toml: python -m pip install -e '.[gpu-graph,orb]'.
# See README.md for the platform limits of this file.
#
# Deliberately not installed, the base environment provides them: torch, numpy, scipy, ase and tqdm (the versions
# fastmd runs with stay in place), and the other dependencies of these packages: requests, filelock,
# huggingface-hub, packaging, rich, python-dateutil, urllib3, cffi and protobuf. `pip check` still reports
# google-crc32c, google-resumable-media, proto-plus, opentelemetry-api and pyasn1-modules as missing and cached-path's
# rich < 14 as unmet: ORB imports, loads and runs without them.
#
# orb-models 0.5.4 pins dm-tree 0.1.8 and imports cached-path, its checkpoint downloader, at module level;
# cached-path 1.8.10 imports its Google Cloud Storage and S3 clients when it is imported, so those are listed too.
# The source MD adapter was validated on orb-models 0.5.4.
